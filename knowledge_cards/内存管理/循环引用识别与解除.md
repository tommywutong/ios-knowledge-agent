# 循环引用识别与解除

## 一句话总结

Block 捕获对象时强持有该对象，当对象也持有 Block 时形成双向强引用环，此时需要使用 weak-strong dance：`weakSelf` 断环，`strongSelf` 保证 Block 执行期间对象不被释放，两者解决不同问题，不可混淆为 "一个操作的两个步骤" [2][9]。

## 核心原理

1. **循环引用的形成机制**
   Block 捕获对象时会强持有该对象（引用计数 +1）[3]。当对象（如 ViewController）持有一个 Block 属性，且该 Block 内部捕获了对象的 `self`，就会形成双向强引用环，导致双方都无法释放 [2]。

2. **weak-strong dance 的原理**
   - 外部定义 `__weak typeof(self) weakSelf = self`：使用弱引用打破环，weak 不增加引用计数，对象可正常释放 [10][2]。
   - Block 内部将 `weakSelf` 赋值给局部强引用（如 `__strong typeof(weakSelf) strongSelf = weakSelf` 或重名的局部 `self`）：临时强持有对象，防止 Block 执行到一半对象被释放（即 "防中途消失"）[2][9]。
   - 该局部强引用只在 Block 作用域内有效，Block 结束后自动释放，因此不会形成新的循环引用 [9]。

3. **实例变量访问规则**
   在 Block 内直接使用 `_ivar` 会被编译器翻译为 `self->_ivar`，而此处的 `self` 是原始捕获的强引用（而非局部 weak/strong 变量），会重新造成循环引用。必须通过局部 self 变量访问，例如 `s->_ivar` [6][12]。

## 关键细节与易错点

- **weakSelf 与 strongSelf 职责分离**：`weakSelf` 负责断环，`strongSelf` 负责保活。理解这一点才能解释 "为什么 strongSelf 不会造成新环" [2][9]。
- **Block 执行时 self 可能已释放**：若对象在 Block 执行前已被销毁，`weakSelf` 为 `nil`，`strongSelf` 也为 `nil`，因此必须先做 nil 检查（如 `if (!strongSelf) return;`）[2][6]。
- **隐式捕获实例变量**：Block 中直接使用 `_token` 会隐式捕获原始 `self`（强引用），导致循环引用，必须改用 `self->_token`（此 `self` 为局部弱/强变量）[6]。
- **代理使用 weak**：delegate 常用 weak 修饰，因为 delegate 通常持有代理对象，用 weak 避免循环引用；若代理对象生命周期短于委托对象，也可用 strong，但需理解所有权关系 [10]。
- **MVVM 中的固定税**：MVVM 架构中每个绑定（如 observe）都要写一遍 weak-strong dance，属于无法避免的模板代码 [7]。
- **替代方案**：某些库（如 MABGTimer）设计为 Block 不捕获 self，而是将对象弱引用作为参数传入，从而避免循环引用 [11][12]。
- **Block 类型影响**：栈 Block、堆 Block、全局 Block 在捕获对象时机制不同（需 copy 到堆上才会强持有），但核心循环引用场景通常发生在堆 Block 上 [9]。

## 高频追问

1. **为什么加了 `strongSelf` 不会造成新的循环引用？**
   `weakSelf` 是弱引用，不增加引用计数；`strongSelf` 只在当前 Block 作用域内临时强持有对象，Block 执行完毕后该局部强引用被销毁，不会形成永久环 [2][9]。

2. **Block 执行前 self 已释放，Block 还会执行吗？**
   会执行。Block 对象本身可能仍被其他引用持有（如 GCD 的 `dispatch_after` 保留了 Block），但此时 `weakSelf` 为 `nil`，`strongSelf` 也为 `nil`，需通过 nil 检查避免空指针操作 [9]。

3. **Block 内直接使用 `_ivar` 为什么会导致循环引用？**
   编译器将 `_ivar` 展开为 `self->_ivar`，这里的 `self` 是原始强引用（即 Block 所捕获的 `self`），而非局部 `weakSelf`，所以仍构成强引用环 [6][12]。

4. **除了 weak-strong dance，还有哪些避免循环引用的方式？**
   - 将对象的弱引用作为 Block 参数传入，使其不捕获 self（如 MABGTimer 的设计）[11]。
   - 使用 `__block` 修饰变量并在适当时候手动置 nil（需注意 Block 搬运机制，材料未详细展开但属于常见方案，本卡片材料不足，无法提供更多细节）。

5. **weak 与 strong 的根本区别是什么？**
   - strong：强引用，引用计数 +1，拥有对象所有权，对象至少有一条强引用时才存活 [10]。
   - weak：弱引用，引用计数不变，对象释放时 weak 指针自动置 nil，不拥有所有权 [10]。

6. **如何检测循环引用？**
   使用 Xcode 的 Memory Graph Debugger 验证 [4]，详见官方工具文档（具体步骤本卡片材料未提供）。
