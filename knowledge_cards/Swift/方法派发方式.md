# 方法派发方式

## 一句话总结

Swift 方法派发分为**静态派发**（直接调用）、**动态派发**（vtable 或 witness table）和 **Objective-C 消息派发**（objc_msgSend），派发方式由类型、修饰符（`final`、`private`、`@objc dynamic`）以及调用上下文（编译器能否确定具体类型）共同决定。

## 核心原理

- **静态派发（Static Dispatch）**：编译器在编译时直接确定调用地址，性能最高。应用场景包括：结构体的所有方法默认静态派发 [11]；类方法使用 `final` 或 `private` 修饰后，编译器可去虚拟化（devirtualize）为静态派发 [11][12]；Objective-C 中可使用 `__attribute__((objc_direct))` 或 `@property (nonatomic, direct)` 将方法声明为直接派发（即静态派发）[9]。
- **动态派发（Dynamic Dispatch）**：运行时分发，支持多态。
  - **vtable 派发（Virtual Table Dispatch）**：Swift 类方法默认使用 vtable 动态派发，允许子类重写 [11]。
  - **见证表派发（Witness Table Dispatch）**：用于协议方法的多态调用。当通过协议类型调用方法、且编译器无法确定具体类型时，通过协议见证表（Protocol Witness Table）动态派发 [3][7]。值见证表（Value Witness Table）管理协议类型的生命周期，协议见证表负责方法调用 [7]。
- **消息派发（Message Dispatch）**：使用 `@objc dynamic` 标记的方法采用 Objective-C 的消息机制（objc_msgSend）派发 [6]。

## 关键细节与易错点

1. **协议扩展方法不是协议要求时，总是静态派发**。即使调用者类型是协议类型（existential），也会直接调用扩展中的实现，无法被重写。因为协议见证表只包含协议自身定义的方法，扩展中额外定义的方法不会进入见证表 [2][5]。这一行为常被开发者视为“不直观” [5]。
2. **`final` 和 `private` 可促进去虚拟化**：对 App 层（非 framework）的类，建议默认加 `final`，这样编译器能生成 `function_ref` 而非 `class_method` 指令，减小 Sema 开销并提升运行时速度 [11][12]。
3. **见证表派发的条件**：协议方法并不总是通过见证表动态派发，**派发方式取决于调用时编译器是否能确定具体类型**。如果能确定具体类型（如直接调用结构体实例上的协议方法），编译器可能使用静态派发 [3]。
4. **`dispatch_once` 与 static 的配合**：常见于 Objective-C 单例模式，保证线程安全的唯一初始化 [1]；也可用于 `+initialize` 方法，避免多次执行 [4]。
5. **Swift 与 Objective-C 互操作时的方法派发**：通过 `@objc dynamic` 标记的方法使用消息派发，这为 KVO、Core Data 等运行时特性提供支持 [6][8]。

## 高频追问

**Q1：类方法默认是动态派发吗？如何改成静态派发？**
是的，Swift 类方法默认通过 vtable 动态派发 [11]。使用 `final` 关键字修饰类或方法，或 `private` 修饰方法（编译器可推断无子类重写）可转为静态派发 [11][12]。

**Q2：为什么协议扩展中定义的方法不能被重写？**
因为协议扩展中的方法不是协议要求，编译器不会将其加入协议见证表。当通过协议类型调用时，唯一能做的就是静态调用扩展中的版本 [2]。若想实现多态，必须将该方法声明为协议要求（即写在协议定义里）。

**Q3：`@objc dynamic` 的作用是什么？**
使 Swift 方法采用 Objective-C 的消息派发（objc_msgSend）[6]。这允许运行时动态替换方法（如 Method Swizzling），也为 KVO 等基于消息机制的 API 提供支持。

**Q4：结构体的方法一定是静态派发吗？**
结构体的方法默认是静态派发 [11]，但若结构体遵循协议并通过协议类型调用（如 `let obj: SomeProtocol = myStruct`），且编译器无法确定具体类型时，会通过见证表动态派发 [3]。

**Q5：`dispatch_once` 在方法派发中有什么关联？**
`dispatch_once` 本身不直接属于派发机制，但在实现单例或 `+initialize` 的线程安全初始化时，与 `static` 关键字配合使用，保证块代码仅执行一次 [1][4]。这属于静态初始化模式的实践。
