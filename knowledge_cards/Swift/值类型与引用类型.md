# 值类型与引用类型

## 一句话总结

值类型（struct、enum）的变量直接持有数据，赋值时产生独立拷贝；引用类型（class）的变量持有指向堆上实例的引用，赋值时拷贝引用，多个变量可能共享同一对象。[1][2][9]

## 核心原理

- **值语义（Value Semantics）**：数据直接存储在变量、参数或属性的存储位置中。赋值操作会复制整个数据，新旧副本完全独立。例如 `struct Point { var x: Int; var y: Int }`，赋值 `b = a` 后修改 `b.x` 不影响 `a.x`。[1][3][9]
- **引用语义（Reference Semantics）**：数据存储在堆（heap）上的对象中，变量或属性只存储对该对象的引用（指针）。赋值操作复制引用，两个引用指向同一个对象。修改对象属性会通过所有引用可见。[1][2][4][9]
- Swift 中：`class` 类型具有引用语义；`struct`、`enum` 具有值语义。[1] 数组（`Array`）、字典（`Dictionary`）和字符串（`String`）等标准库集合类型虽然内部可能使用类实现，但对外提供值语义，采用写时复制（Copy-on-Write）技术。[1][5][6]
- **实现值语义的常见模式**：在结构体内部使用引用类型（class）作为存储后端，并通过写时复制保证结构体赋值时产生独立副本。例如 Swift 标准库中的集合类型。[1][3][5][6]

## 关键细节与易错点

- **类（class）的构造开销更高**：因为需要在堆上分配内存、管理引用计数，并且可能涉及锁定堆等操作；结构体（struct）通常使用栈或内联存储，无堆分配。[4]
- **值类型复制成本**：如果值类型包含大量内联存储属性，多次拷贝会占用更多内存和复制时间；而引用类型（class）的拷贝只复制指针，共享底层数据。[6] 两者各有优劣，无绝对规则。
- **结构体内部包含引用类型字段时**：结构体本身是值类型，但其字段（如 class 字段）仍是引用语义。赋值结构体时，该引用字段的引用计数会正确递增/递减。可以利用此特性在结构体“销毁”时执行副作用（如通过 `OnDelete` 类在 `deinit` 中运行闭包），但这不是真正的 `deinit` 方法。[10][7]
- **值类型的引用循环问题**：结构体不能使用 `weak` 捕获自身，因为 `weak` 需要引用类型。如果结构体内部包含引用类型字段并形成循环，需要手动打破循环（例如使用 `class` 类型并添加 `weak` 从子到父的链接）。[7]
- **闭包捕获结构体的语义**：捕获可变值类型时存在细微差别，需注意引用计数循环可能发生在包含 class 字段的结构体上。[7]
- **结构体不能自定义赋值或析构**：Swift 不允许对结构体的赋值操作或销毁过程进行自定义（如 `deinit`）。为弥补，标准库采用“struct 包裹 class”的模式实现写时复制。[3][10]

## 高频追问

**Q1: 什么时候用 struct 而不是 class？**
材料直接给出的原则：**用 struct 当需要值语义，用 class 当需要引用语义。** [1][2][9] 此外，如果不需要继承、不需要 identity（身份标识）且不需要间接存储，考虑使用 struct 性能更好。[4][5]

**Q2: Swift 集合类型（Array, Dictionary, String）是值类型还是引用类型？它们内部如何实现值语义？**
它们对外表现为值类型（struct），但内部使用引用类型（class）存储元素，并通过 **写时复制（Copy-on-Write）** 技术保证：在多个副本共享同一底层存储时，只有当某个副本发生修改时才创建新的独立副本。这是 struct 包裹 class 实现值语义的典型模式。[1][3][5][6]

**Q3: 结构体可以有析构函数（deinit）吗？**
不能。结构体没有 `deinit`，但可以利用其内部引用类型字段在引用计数归零时触发 `deinit` 来模拟析构行为（如 `OnDelete` 对象）。注意这并非真正的结构体析构，而是通过成员对象的生命周期附加副作用。[10]

**Q4: 值类型和引用类型在函数传参时的行为差异？**
材料未直接讨论函数传参时的语义，但有暗示：值类型传参会拷贝整个值（可能使用写时复制优化），引用类型传参拷贝引用。[1][2] 具体到函数参数，`inout` 关键字可以修改传入的值类型变量，但函数内修改对调用者可见需 `inout` 标记。[材料未覆盖更细节，可参考 Swift 语言指南]

**Q5: 结构体是否一定存储在栈上？**
材料指出：结构体使用“内联存储”（inline storage），即数据直接存在于变量所在位置（栈或堆中的对象内），但并未绝对说“结构体一定在栈上”。当结构体是类中的一个属性时，它存储在堆上对象的内部。[4][6] 因此，“结构体总在栈上”是不准确的。

**Q6: Swift 中的 class 有哪些引用语义特有的特性？**
材料提到 class 具有 **身份标识（identity）**、**间接存储** 以及堆分配带来的灵活性（如启用 `weak` 引用打破循环）。[4][7] 如果不需要这些特性，用 struct 更好。
