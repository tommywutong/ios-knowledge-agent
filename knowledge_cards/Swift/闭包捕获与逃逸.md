# 闭包捕获与逃逸

## 一句话总结
Swift 闭包默认是非逃逸的，逃逸闭包需显式使用 `@escaping`；闭包捕获列表（Capture List）允许指定捕获强度（`weak`、`unowned`、`unowned(safe)`、`unowned(unsafe)`）以管理引用循环，且非逃逸闭包不可能造成引用循环，编译器对此进行了优化。

## 核心原理

- **逃逸与非逃逸的区分**：
  Swift 的闭包分为逃逸（`escaping`）和非逃逸（`non-escaping`）。逃逸闭包可能在函数返回后才被调用（如网络请求回调）；非逃逸闭包在函数结束前一定执行完毕。Swift 默认使用 `non-escaping`，逃逸闭包须显式声明 `@escaping`。[1]

- **内存管理差异**：
  闭包对捕获的每个对象保持强引用（strong reference），包括通过隐式 `self` 访问属性或实例方法时的 `self`。[4]
  - 非逃逸闭包：编译器保证在函数返回前释放所有捕获对象，因此不可能创建引用循环，编译器不要求显式写出 `self.`。[4]
  - 逃逸闭包：可能形成引用循环，编译器强制要求显式写出 `self.` 以提醒开发者手动处理（使用捕获列表）。[1][4]

- **捕获列表（Capture List）**：
  捕获列表放在闭包的方括号内，可指定捕获强度：`weak`、`unowned`、`unowned(safe)`、`unowned(unsafe)`，也可绑定任意表达式到命名值。[7][8][9]
  示例：
  ```swift
  takeClosure { [weak self] in print(self!.title) }    // weak capture
  takeClosure { [unowned self] in print(self.title) }  // unowned capture
  [unowned self, weak delegate = self.delegate]         // 混合捕获 [9]
  ```

- **闭包是堆上存储的代码块**：
  闭包本身是一个存储于堆上的代码块，独立于创建它的类。因此，即使在闭包内部再次使用 `[weak self]`，捕获的仍然是外层闭包中隐式强引用的 `self` 副本，而非原始实体。[3]

## 关键细节与易错点

- **逃逸闭包必须显式 `@escaping`**：
  Swift 默认非逃逸，若函数需要存储闭包或以异步方式调用，则必须标记 `@escaping`。[1]

- **非逃逸闭包避免引用循环**：
  非逃逸闭包的生命周期受限于函数作用域，编译器可保证所有捕获对象在函数返回前释放，因此不会产生引用循环。[4]

- **捕获列表放在 `in` 之前**：
  若闭包有参数列表或返回类型，捕获列表放在参数列表之前；若无，则放在闭包最开头，紧跟 `in` 关键字。[9]

- **`@Sendable` 与逃逸闭包**：
  在启用 Swift 6 严格并发检查时，若逃逸闭包被传递给 `@Sendable` 闭包（如 `Task`），需要将闭包也标记为 `@Sendable`，否则编译器会警告“Capture of 'then' with non-sendable type”。标记为 `@Sendable` 后，闭包按值捕获参数，避免数据竞争。[2]

- **多层闭包中 `weak self` 的位置**：
  在 Combine 的 `.sink` 中内部再开 `Task` 时，若只在 `Task` 内部使用 `[weak self]`，则 `Task` 捕获的是 `.sink` 闭包中隐式强引用的 `self`，导致引用循环。正确做法是将 `[weak self]` 放在外层 `.sink` 闭包的捕获列表中。[3]

- **结构体无法使用 `weak` 捕获**：
  若捕获的是结构体（`struct`），无法使用 `[weak self]`，因为结构体是值类型。在初始化方法中捕获 `self` 可能创建不可打破的循环（因为 `init` 返回的副本与闭包捕获的副本不同），需要避免在 escaping 闭包中捕获 `inout` 的 `self`。[5]

- **捕获列表的强度说明**：
  捕获列表支持 `weak`、`unowned`、`unowned(safe)`、`unowned(unsafe)`，其中 `unowned` 默认是 `unowned(safe)`。[8]

## 高频追问

**Q1: 为什么非逃逸闭包不需要显式写出 `self.`？**
A: 因为非逃逸闭包在函数返回前必定执行完毕，编译器能保证不会产生引用循环，因此不强制要求显式引用 `self`，让代码更简洁。[4]

**Q2: 逃逸闭包为什么一定要写 `self.`？**
A: 逃逸闭包可能延迟执行，容易意外造成强引用循环。强制要求显式 `self.` 迫使开发者思考捕获语义，并手动通过捕获列表解决循环引用。[1][4]

**Q3: 如何在多层嵌套闭包中正确避免循环引用？**
A: 应在最外层的闭包捕获列表中使用 `[weak self]`，而不是仅在内部闭包中使用。例如 Combine 的 `.sink` 和内部 `Task` 的组合：要在 `.sink` 的捕获列表中写 `[weak self]`，内部 `Task` 不需要再写 `[weak self]`，因为外层已确保弱引用。[3]

**Q4: 捕获列表中的 `weak` 和 `unowned` 有何区别？**
A: `weak` 捕获的引用变为弱引用，当所引用对象被释放时自动变为 `nil`，因此需要在闭包内使用可选链；`unowned` 捕获的引用假定对象在闭包整个生命周期内都不会被释放，如果对象提前释放会导致崩溃。[7][10]（注：材料 [7] 指出 `unowned` 捕获可直接访问 `self.title`，但未详细对比两者区别；材料 [8] 列出语法支持 `unowned(safe)` 和 `unowned(unsafe)`。）

**Q5: 结构体（struct）的捕获会形成引用循环吗？**
A: 结构体是值类型，通常不会形成引用循环，但在初始化方法中（`init`）使用 escaping 闭包捕获 `self`（如 `inout` 捕获）可能创建不可打破的循环，因为 `init` 返回的副本与闭包捕获的副本不同，注意避免这种模式。[5]
