# 单元测试与依赖注入

## 一句话总结
依赖注入（Dependency Injection）是让单元测试变得容易的核心实践——通过将外部依赖以参数或属性注入的方式传入，测试时可以将其替换为可控的测试替身（stub/mock），从而实现快速、可重复的测试。

## 核心原理

- **依赖注入使测试替身更容易使用**。如果不使用依赖注入，有时可以通过 mock 类方法等方式绕过，但往往不可行或设置复杂度超过收益；而一致使用依赖注入后，编写使用 stub 和 mock 的测试会简单得多 [1]。
- **使用 mock 对象通常需要某种形式的依赖注入**。例如通过构造函数注入（constructor injection）将 `UIApplication` 实例传入待测对象，这样测试时就可以注入 mock 对象来验证 `openURL:` 是否被正确调用 [2]。
- **依赖注入解决的核心问题**：当方法依赖另一个对象（如 `NSUserDefaults`）且该对象会让测试失去快速性和可重复性时，通过注入可以替换该依赖 [5]。
- **TCA（The Composable Architecture）中依赖注入是内置系统**。通过定义依赖客户端（如 `NumberFactClient`）、实现 `DependencyKey` 并注册到 `DependencyValues`，在 Reducer 中使用 `@Dependency` 属性包装器获取；并强制提供三个值：`liveValue`（生产）、`testValue`（测试，未实现时调用会直接失败，强制显式 mock）、`previewValue`（预览）[12]。

## 关键细节与易错点

- **依赖注入让测试设置更简单**：如果不一致使用依赖注入，测试设置的复杂度可能超过收益 [1]。
- **Swift 中可以不依赖 OCMock 实现 mock**：利用 Swift 在方法中内嵌类型的特性，或者手写符合协议的 test double [3][8]。
- **OCMock 的限制**：它依赖 Objective-C 动态运行时；纯 Swift 代码（不继承 `NSObject`、无 `@objc` 注解）无法使用 OCMock [8]。
- **XCTest 配置注意点**：测试目标是一个独立 target，应用源文件只加入应用 target，测试代码只加入测试 target；需要设置 Test Host 和 Bundle Loader [7]。
- **UI 测试（XCUITest）通过辅助功能（AX）树与 App 交互**：`XCUIElement` 是 AX 元素的代理；不设置 AX 属性的自绘控件在 UITest 中无法点击；`accessibilityIdentifier` 是测试专用 ID，不朗读，适合机器识别 [9]。
- **iOS 17+ XCTest 提供自动化审计**：通过 `performAccessibilityAudit()` 可以检查对比度、动态类型、元素检测等，适合加入 CI 回归 [10]。
- **服务层依赖的设计原则**：推荐将带副作用的依赖封装成协议，最小化包装依赖特性，简化接口；不要将应用逻辑放入服务层，因为服务本身是不可测试的依赖 [11]。

## 高频追问

**1. 依赖注入有哪些具体方式？**
材料中提到了构造函数注入（constructor injection）——通过 `initWithApplication:` 注入 `UIApplication` 对象 [2]；以及在 TCA 中通过 `@Dependency` 属性包装器注入（实质是依赖查找/属性注入）[12]。未讨论其他方式（如 setter 注入、接口注入）。

**2. Swift 中不依赖 OCMock 如何实现 mock？**
可以使用纯 XCTest，通过手写符合协议的 test double 类/结构体来模拟依赖 [3][8]；或者利用 Swift 语言自身可以在方法内嵌类型的特性来创建临时 mock [3]。

**3. UI 测试（XCUITest）中为什么要使用 `accessibilityIdentifier`？**
因为 `accessibilityLabel` 会随语言变化，而 `accessibilityIdentifier` 是固定不朗读的标识符，适合机器识别，保证跨语言的测试稳定性 [9]。

**4. TCA 的 `testValue` 强制 mock 有什么意义？**
防止测试时不小心用到 `liveValue` 导致实际的外部副作用（如网络请求）；未实现 `testValue` 时在测试中调用会直接失败，迫使开发者显式提供可控的 mock 实现 [12]。

**5. 为什么说依赖注入能保证测试的快速和可重复？**
材料中以 `NSUserDefaults` 为例指出：依赖另一个对象会使测试变慢或结果不可重复；而通过依赖注入替换为可控的测试替身后，测试就能脱离外部依赖，变得快速且可重复 [5]。
