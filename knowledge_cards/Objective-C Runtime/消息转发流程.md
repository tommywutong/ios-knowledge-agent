# 消息转发流程

## 一句话总结

当对象收到无法响应的消息时，Runtime 会依次经过动态方法解析、快速转发和完整转发三个阶段，每个阶段都提供扩展点；如果三个阶段均未处理，最终调用 `doesNotRecognizeSelector:` 抛出异常。[11][12]

## 核心原理

消息转发流程由底层 `__forwarding__` 函数（或 `___forwarding___`）驱动，在消息查找失败后自动执行。[1] 整个转发分为三个阶段：

### 第一阶段：动态方法解析（Dynamic Method Resolution）

Runtime 调用 `+resolveInstanceMethod:`（实例方法缺失时）或 `+resolveClassMethod:`（类方法缺失时），开发者可在内部通过 `class_addMethod` 动态添加方法实现。如果返回 YES 且成功添加方法，Runtime 会重新发送消息。[11] 此阶段默认不处理。[12]

### 第二阶段：快速转发（Fast Forwarding）

如果动态方法解析未处理，Runtime 调用 `-forwardingTargetForSelector:`（实例方法）或 `+forwardingTargetForSelector:`（类方法）。[2][11]
开发者返回一个备用对象来接收该消息。Runtime 会直接对备用对象执行 `objc_msgSend`，不创建 `NSInvocation`，效率高。[1][11]
如果返回 `nil` 或返回自己（`forwarding == receiver`），则继续下一阶段。[1]
类方法的快速转发同样生效，但 Xcode 不会自动补全。[2]

### 第三阶段：完整转发（Normal Forwarding）

如果快速转发返回 `nil`，`__forwarding__` 会先调用 `-methodSignatureForSelector:`（或 `+methodSignatureForSelector:`）获取方法签名（`NSMethodSignature`）。[1][3][4][8][9]
- 如果返回 `nil`，Runtime 无法构造 `NSInvocation`，直接走兜底 `doesNotRecognizeSelector:`。[5][8][9]
- 如果返回有效签名，Runtime 用该签名构造 `NSInvocation`，再调用 `-forwardInvocation:`（或 `+forwardInvocation:`）。[1][3][4][8][9]

在 `forwardInvocation:` 中，开发者可以修改 target、参数、返回值，转发给多个对象，或延迟调用。[4][6][11]
完整转发性能开销最大，但灵活性最高。[11]

### 最终兜底：`doesNotRecognizeSelector:`

如果上述三个阶段都没有处理，Runtime 调用 `doesNotRecognizeSelector:`，抛出 `unrecognized selector` 异常。[10][11][12]

> 类方法的转发流程与实例方法一致，只需重写对应的类方法版本。[2]

## 关键细节与易错点

### 1. 快速转发的限制
- 无法修改消息参数、返回值。[11]
- 只能转给单一对象，不能多路转发。[11]
- 如果返回 `nil`，消息会继续进入完整转发。[1]

### 2. 完整转发必须两步都要实现
`methodSignatureForSelector:` 负责提供方法签名，`forwardInvocation:` 负责实际处理。如果签名返回 `nil`，系统连 `NSInvocation` 都构造不出来，直接进入 `doesNotRecognizeSelector:`。[5][8][9]
调用顺序：`methodSignatureForSelector:` → 构造 `NSInvocation` → `forwardInvocation:`。[1][3][4]

### 3. 方法签名与编译器的一致性检查
`__forwarding__` 内部会检查 `methodSignatureForSelector:` 返回的签名中关于“是否返回 struct”的标志与编译器判断是否一致（`signatureIsStret != isStret`），不一致时输出警告日志。[1][10]

### 4. 僵尸对象检测
快速转发阶段中，`__forwarding__` 会检查接收者的类名是否以 `_NSZombie_` 开头，若是则输出“message sent to deallocated instance”错误并中断。[1]

### 5. 完整转发的典型应用
- **多路转发**：将 `NSInvocation` 分发给多个目标，注意非 void 返回值的方法只能取一个目标的返回值。[6]
- **组合对象能力透传**：模拟多继承，让一个对象将消息转发给多个内部对象。[6]
- **延迟执行或日志**：修改 target、参数、返回值等。[4][5][11]
- **Future/Proxy 模式**：如 Mike Ash 的 Compound Futures，在 `forwardInvocation:` 中处理已解析或未解析的 future 值。[7]

### 6. `doesNotRecognizeSelector:` 的兜底逻辑
`__forwarding__` 最后会检查 selector 是否与 Runtime 已注册的 selector 一致（`sel != registeredSel`），不一致则输出警告；否则调用 `doesNotRecognizeSelector:`，若该方法未实现则输出 abort 日志。[10]

### 7. 所有转发方法定义在 `NSObject` 中
默认实现均为“不处理”（返回 NO / 返回 nil / 抛异常），继承自 `NSObject` 的类可通过重写介入转发。[12]

## 高频追问

### Q1: 消息转发三个阶段的执行顺序是怎样的？
**A:** 第一阶段：动态方法解析（`resolveInstanceMethod:` / `resolveClassMethod:`）；第二阶段：快速转发（`forwardingTargetForSelector:`）；第三阶段：完整转发（`methodSignatureForSelector:` + `forwardInvocation:`）。三个阶段都未处理时，最终调用 `doesNotRecognizeSelector:` 抛出异常。[11][12]

### Q2: 快速转发和完整转发有什么区别，如何选择？
**A:** 快速转发只返回一个备用对象，Runtime 直接对备用对象发送原消息，不创建 `NSInvocation`，效率高但无法修改参数、返回值或转发给多个对象。[11]
完整转发需要两个方法，可完全控制调用过程（修改 target、参数、返回值、多路转发等），性能开销最大。[4][6][11]
**选择原则**：只是换一个对象接收，用快速转发；需要日志、改参数、延迟、多路转发等，用完整转发。[5][11]

### Q3: 如果 `methodSignatureForSelector:` 返回 `nil` 会发生什么？
**A:** Runtime 无法构造 `NSInvocation`，不会调用 `forwardInvocation:`，直接跳转到 `doesNotRecognizeSelector:` 抛出异常。[5][8][9] 同时 `__forwarding__` 会输出警告日志。[1][10]

### Q4: 类方法能否进行消息转发？如何实现？
**A:** 可以。对应重写 `+resolveClassMethod:`、`+forwardingTargetForSelector:`（类方法版本）、`+methodSignatureForSelector:` 和 `+forwardInvocation:`。注意 Xcode 不会自动补全这些类方法版本。[2]

### Q5: `forwardingTargetForSelector:` 返回 `self` 或 `nil` 会怎样？
**A:** 返回 `nil` 或返回接收者自身（`forwarding == receiver`）时，`__forwarding__` 会跳过快速转发，进入完整转发或兜底。[1] 返回 `nil` 最常见。

### Q6: 完整转发中如何将消息转发给多个对象？
**A:** 在 `forwardInvocation:` 中遍历目标数组，对每个响应的目标调用 `[invocation invokeWithTarget:target]`。注意只有返回值类型为 `void` 的方法才适合继续分发给多个对象；非 void 返回值的方法只能选择一个目标的返回值。[6]

### Q7: 僵尸对象的检测发生在哪个阶段？
**A:** 在快速转发阶段中，`__forwarding__` 在执行 `forwardingTargetForSelector:` 之后，会检查接收者的类名是否为 `_NSZombie_` 前缀。若匹配，直接输出错误日志并中断，不再继续转发。[1]

### Q8: 是否可以在不实现 `methodSignatureForSelector:` 的情况下使用 `forwardInvocation:`？
**A:** 不可以。`forwardInvocation:` 必须在 `methodSignatureForSelector:` 返回有效签名后才会被调用；签名返回 `nil` 则直接崩溃。[3][4][5][8][9]
