# 类对象与元类

## 一句话总结
元类是描述类对象的类，它和普通类共用 `objc_class` 结构体，仅靠**标志位**区分 [8]；类方法实质是元类的“实例方法”，消息查找通过 `isa` 链和 `superclass` 链完成 [1][5][12]。

## 核心原理

1. **类对象与元类的关系**
   - Objective-C 的 `Class` 是一个指向 `objc_class` 结构体的指针，`objc_class` 继承于 `objc_object`，因此类本身也是一个对象 [4][9]。
   - 类对象的 `isa` 指向元类（meta‑class），元类是类对象的类；实例对象的 `isa` 指向类对象 [2][3]。
   - 元类的主要职责是存储**类方法**（class method）的实现及管理类方法相关的元数据 [1][2]。

2. **`isa` 链与 `superclass` 链**
   - **`isa` 链**：实例对象 → 类对象 → 元类对象 → 根元类（`NSObject` 的元类）→ 根元类的 `isa` 指向自身，形成闭环 [3][9][11]。
   - **`superclass` 链**（继承链）：
     - 类对象：`SubClass → SuperClass → … → NSObject → nil`
     - 元类对象：`SubClass 元类 → SuperClass 元类 → … → 根元类 → NSObject 类对象 → nil`
     - 根元类的 `superclass` 指向 `NSObject` 类对象，而非 `nil`，这使得 `NSObject` 的实例方法可以作为类方法调用的兜底（例如 `[NSObject description]` 会沿元类 superclass 回溯到 `NSObject` 类对象找到 `-description`）[3][11][12]。

3. **类方法本质上是元类的实例方法**
   - 源码实现直白：`class_getClassMethod(cls, sel)` 内部调用的是 `class_getInstanceMethod(cls->getMeta(), sel)`，即去元类中查找同名实例方法 [5]。
   - 元类的 `method list` 中存储类方法 [2]；向类对象发送消息时，`objc_msgSend()` 根据类对象的 `isa` 找到元类，并在其方法列表中查找响应 [1][2][9]。

4. **元类与普通类共用同一个结构体**
   - 元类**没有**独自的结构体定义，它和普通类共用 `objc_class`，仅靠标志位（如 `RW_META` 或 cache 中的 `FAST_CACHE_META`）来区分是否为元类 [8]。
   - 标志位位于 `class_rw_t` / `class_ro_t` 起始处的 `flags` 字段，便于在 realize 前后都能快速判断 [8]。

5. **元类的唯一性**
   - 每个 `Class` 对象都有自己唯一的元类（因为每个类可以拥有自己唯一的方法列表）[7]。
   - 所有元类（包括根元类）的 `isa` 都指向根元类，根元类的 `isa` 指向自身 [2][11]。

## 关键细节与易错点

- **元类对象的 `isa` 与 `superclass` 终点不同**：所有元类的 `isa` 都指向根元类；根元类的 `superclass` 指向 `NSObject` 类对象，而 `NSObject` 类对象的 `superclass` 为 `nil` [3][9][11]。
- **类方法查找的兜底路径**：当根元类中找不到 `+` 方法时，会沿 `superclass` 回溯到 `NSObject` 类对象，此时找到的是实例方法（`-` 方法），因此 `NSObject` 的实例方法可作为类方法调用 [3][12]。
- **元类标志位与类型安全的陷阱**：因为元类与普通类共用 `objc_class`，不能仅通过结构体类型区分，必须通过 `isMetaClass()` 或 `isMetaClassMaybeUnrealized()` 判断 [8]。
- **继承自 `NSObject` 的 Swift 类中的元类**：Swift 类若需要 ObjC 消息派发（如 `@objc class func`），编译器会在元类的方法列表中注册对应的 thunk，其元类结构与纯 ObjC 元类完全相同，仍是标准的 `objc_class`；普通 Swift 类方法的 Swift 派发不依赖元类 [10]。
- **元类不存储 Swift vtable 或 typeDescriptor**：这些信息只存在类对象上，不需要在元类上重复 [10]。

## 高频追问

**Q1：类方法和实例方法的查找过程有何不同？**
**A**：实例方法查找从类对象的 method list 开始，沿类对象的 `superclass` 链回溯 [3]；类方法查找从元类的 method list 开始，沿元类的 `superclass` 链回溯，最终可能回溯到 `NSObject` 类对象（实例方法）[3][12]。在源码层面，`class_getClassMethod` 本质是调用 `class_getInstanceMethod` 去元类中查找同名选择子 [5]。

**Q2：为什么元类的 `superclass` 要指向 `NSObject` 类对象？**
**A**：这样设计使得类对象可以响应 `NSObject` 的实例方法（如 `description`、`retain`、`release` 等），即当类方法在元类链中找不到时，可通过根元类的 `superclass` 找到 `NSObject` 类对象中的实例方法作为兜底 [3][12]。（本卡片材料未提供更深入的设计原因说明 [11]中提到作者也不确定该设计缘由，故不进一步猜测。）

**Q3：元类存在的根本原因是什么？**
**A**：元类存在的根本原因是让类方法也能通过正常的消息派发机制查找。因为类本身也是一个对象，需要有自己的类（即元类）来存储类方法，实例方法存储在类对象中，类方法存储在元类中，两者使用同一套消息发送机制 [1][5][6][7]。

**Q4：如何判断一个 `objc_class` 是否是元类？**
**A**：调用 `isMetaClass()` 方法（需类已 realize），该方法读取 cache 中的 `FAST_CACHE_META` 位（真机）或 `data()->flags & RW_META`；对于未 realize 的类，可使用 `isMetaClassMaybeUnrealized()`，直接读取 bits 中 `flags` 字段的 `RW_META` 位，因为 `class_ro_t` 和 `class_rw_t` 的 flags 字段位于相同偏移 [8]。
