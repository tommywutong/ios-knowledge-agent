# 离屏渲染

## 一句话总结

离屏渲染（Offscreen Rendering）是 GPU 先在临时纹理（offscreen texture）中绘制层或子树，然后再将结果拷贝到最终帧缓冲区的过程 [8]；它主要触发于阴影、遮罩、圆角（rounded rectangles）和视觉效果四类 offscreen passes [5]，其性能代价取决于内容是否可被重用以及系统版本 [4][7]；现代检测应使用 View Debugging 的染色选项或 Show Layers Inspector，而 Instruments 的 Core Animation 模板已于 Xcode 9.3 废弃 [11]。

## 核心原理

1. **定义与触发场景**
   - 离屏 pass 指 “the GPU must render a layer by first rendering it somewhere else and then copying it over” [8]。
   - 四种主要类型：shadows、masks、rounded rectangles、visual effects（如 vibrancy and blurring）[5]。

2. **阴影的离屏流程**
   - 当 GPU 不知道阴影形状时，先切换到离屏纹理，绘制所有子层变为黑色并模糊，得到阴影形状；再将离屏纹理拷贝回最终纹理，继续绘制其他内容 [8]。

3. **遮罩与圆角的离屏条件**
   - 遮罩离屏：渲染器需要先渲染整个被遮罩子树，再只拷贝遮罩形状内的像素回最终纹理 [5]。
   - 圆角离屏：**不是必然触发**，取决于渲染器是否有足够信息以及是否有需要裁剪的子层（sublayer）[6]。Apple 2020 年表述为 “can sometimes require an offscreen” [5][6]。

4. **缓存与重用**
   - 如果离屏渲染的结果可以被 Core Animation 缓存（即参与合成的层内容不变），则可能提升性能；缓存空间大约为屏幕大小的两倍 [7]。
   - 当通过 `shouldRasterize` 开启光栅化时，必须同时设置 `rasterizationScale` 为 `contentsScale` [7]。

5. **性能代价**
   - 离屏渲染需要**上下文切换**（GPU 切换到不同内存区域）、拷贝结果到帧缓冲，并消耗额外显存 [10]。
   - 任何参与离屏合成的层发生变化时，缓存需要全部重绘 [10]。

6. **避免离屏渲染的常见方案**
   - 若图层内容**不常变化**，可开启光栅化（`shouldRasterize = YES`）以重用缓存 [9]。
   - 若内容**经常变化**，则使用 `CAShapeLayer`、`contentsCenter` 或 `shadowPath` 实现类似视觉效果，避免离屏渲染 [9]。
   - 圆角场景：`cornerRadius` 和 `masksToBounds` 只有**一起使用**才会引起离屏渲染；可通过 `CAShapeLayer` 配合 `UIBezierPath` 绘制需要圆角的区域而不触发离屏 [2]。

## 关键细节与易错点

- **圆角是否触发离屏的条件式说法**
  “iOS 9 后纯色背景不再触发”这一版本号叙事**没有 Apple 官方声明支持**（release notes、WWDC、文档均无）[6]。真实条件是：
  - 渲染器是否有足够信息（例如纯色背景且无子层时，不需要 `masksToBounds` 也能展示圆角，自然绕开离屏）[6]。
  - 是否有需要裁剪的 sublayer [6]。

- **区分离屏 pass 与其他 GPU 操作**
  必须区分 offscreen pass、blending（混合）、CPU drawing（CPU 绘制）和 raster cache（光栅缓存），不能统一称为“离屏渲染” [4]。

- **Instruments Core Animation 模板已废弃**
  Xcode 9.3 release notes 明确废弃该模板及对应的 Debug 选项 [3][11]；正确检测方法：
  - Xcode `Debug > View Debugging > Rendering > Color Offscreen-Rendered Yellow` 染色 [11]。
  - 在 View Debugger 中选中某个 layer，Inspector 可直接显示 offscreen count 和 offscreen flags（如 `offscreen mask`）[11]。
  - `Editor > Show Optimization Opportunities` 会在 Runtime Issue Navigator 中给出具体优化建议 [11]。
  - 帧率检测应使用 Instruments 的 **Animation Hitches** 模板，其 render count 对应 GPU 离屏 pass 次数 [11]。

  **注意**：仍有部分材料（如 [12]）描述 Core Animation 模板的使用步骤，但该模板已不可用于现代 Xcode [11]。

- **内存与上下文切换**
  离屏渲染需要额外视频内存，且每次内容变化都需重新离屏绘制，因此对于动态频繁的图层应避免 [10]。

## 高频追问

**Q1：如何在真机上确认一个图层发生了离屏渲染？**
A：使用 Xcode `Debug > View Debugging > Rendering > Color Offscreen-Rendered Yellow`，被离屏渲染的图层会显示为黄色。更精确的方法是进入 View Debugger，选中图层后在 Inspector 查看 `offscreen count` 和 `offscreen flags` [11]。

**Q2：shouldRasterize 一定能提升性能吗？**
A：不一定。光栅化本质是将离屏渲染结果缓存，如果图层内容频繁变化（例如每一帧都不同），缓存会反复失效并重绘，反而增加功耗和耗时 [10]。只有当视图变化不频繁时，光栅化才可能抵消离屏渲染的代价 [10]。

**Q3：cornerRadius + clipsToBounds 为什么有时候不离屏？**
A：根据 Apple 2020 年条件式说法，如果渲染器有足够信息（例如纯色背景且无子层需要裁剪），则不需要离屏 pass [6]。此时只需设置 `backgroundColor` 和 `cornerRadius`，无需设置 `masksToBounds` 即可显示圆角，从而自动绕开离屏 [6]。`

**Q4：除了圆角，还有哪些常见操作会触发离屏？**
A：阴影（shadow）、遮罩（mask）、视觉效果（visual effect views，如 UINavigationBar、UITabBar 的毛玻璃和 vibrancy）[5]。

**Q5：有没有办法完全避免离屏渲染？**
A：对于阴影，可以指定 `shadowPath` 让 GPU 知道形状，避免离屏 [4][9]；对于圆角，使用 `CAShapeLayer` 绘制圆角矩形作为内容（不依赖 `masksToBounds`）[2]；对于视觉效果，可考虑用静态背景图片替代动态毛玻璃 [本卡片材料不足，该结论基于常见实践但材料未明确给出]。
