# 事件传递与响应链
## 一句话总结
iOS 事件处理分为两个阶段：**命中测试（Hit-Testing）** 自顶向下递归找到触摸点下最深层的视图；**响应者链（Responder Chain）** 从该视图开始，沿 `nextResponder` 逐级向上传递事件，直到找到能处理的对象。[2][6][9]

## 核心原理

### 阶段一：命中测试（Hit-Testing）
UIKit 通过递归调用 **`hitTest:withEvent:`** 和 **`pointInside:withEvent:`** 来确定哪个视图是触摸事件的“最佳接收者”。[6][4]

-   **`hitTest:withEvent:`**：返回应处理触摸的视图（`UIView *`）[6]。
-   **`pointInside:withEvent:`**：判断触摸点是否在视图的 `bounds` 范围内（`BOOL`）。[6][7]

**系统默认实现逻辑 [8]：**
1.  **入口**：`UIApplication` 将事件传给 `UIWindow`，`UIWindow` 调用自己的 `hitTest:withEvent:`。[1]
2.  **跳过判断**：系统会忽略 `hidden == YES`、`userInteractionEnabled == NO` 或 `alpha < 0.01` 的视图。[4]
3.  **检查范围**：调用 `pointInside:withEvent:` 判断点击点是否在视图 `bounds` 内。如果不在，直接返回 `nil`。[8]
4.  **遍历子视图**：如果点在范围内，则从后往前（`reverseObjectEnumerator`）遍历其子视图。[10][8]
5.  **坐标转换**：对于每个子视图，使用 `convertPoint:fromView:` 将触摸点从父视图坐标系转换到子视图坐标系。[8][10]
6.  **递归调用**：对每个子视图递归调用其 `hitTest:withEvent:`。[8]
7.  **返回结果**：递归过程返回第一个非 `nil` 的子视图作为最终结果。如果所有子视图都返回 `nil`，则返回自己。[1][3][10]

> **示例输出**（`pr_` 为自定义日志前缀，体现了自顶向下递归与回溯的过程）：[1]
```
UIWindow pr_hitTest(_:with:)
 UIWindow --- pr_pointInside
 UIDropShadowView pr_hitTest(_:with:)
  UIDropShadowView --- pr_pointInside
  UILayoutContainerView pr_hitTest(_:with:)
   UILayoutContainerView --- pr_pointInside
   UINavigationBar pr_hitTest(_:with:)
    UINavigationBar --- pr_pointInside
    UINavigationBar pr_pointInside +++ return: false    // 跳过 UINavigationBar
   UINavigationTransitionView pr_hitTest(_:with:)
    UINavigationTransitionView --- pr_pointInside
    ...
    ResponderChain.ViewB1 pr_hitTesting return:ResponderChain.ViewB1 // 找到目标视图
```

### 阶段二：响应者链（Responder Chain）
命中测试结束后，事件从被触摸的视图（即**第一响应者**）开始，沿着 **`nextResponder`** 构建的响应者链向上传递，直到有对象处理该事件。[9][12]

**标准响应者链结构 [9]：**
```
First Responder (UIView) → Superview → UIViewController → UIWindow → UIApplication → AppDelegate
```

`UIResponder` 的核心方法之一：`nextResponder`。[11]

```objc
@interface UIResponder : NSObject
@property(nonatomic, readonly, nullable) UIResponder *nextResponder;
// 触摸事件处理的核心方法
- (void)touchesBegan:(NSSet<UITouch *> *)touches withEvent:(UIEvent *)event;
- (void)touchesMoved:(NSSet<UITouch *> *)touches withEvent:(UIEvent *)event;
- (void)touchesEnded:(NSSet<UITouch *> *)touches withEvent:(UIEvent *)event;
- (void)touchesCancelled:(NSSet<UITouch *> *)touches withEvent:(UIEvent *)event;
@end
```
[11]

**事件处理方式**：在响应者链上的对象可以重写触摸事件方法。如果选择处理，则事件消耗掉；如果不处理，需显式调用 `[super touches...]` 方法将事件传递给 `nextResponder`。[9]

## 关键细节与易错点

1.  **子视图超出父视图 `bounds` 无法响应**：因为父视图的 `pointInside:` 返回 `NO`，导致 hit-testing 根本不会检查其子视图。[10]
    *   **解决方案**：重写父视图的 `pointInside:` 或 `hitTest:withEvent:`，在点不落在父视图 `bounds` 内时，依然手动遍历子视图并转换坐标进行判断。[8][10]

2.  **`transform` 对命中测试的影响**：`pointInside:` 直接在 `bounds` 坐标系下判断，不受 `transform` 影响。`transform` 的作用发生在坐标转换环节：父视图调用 `convertPoint:fromView:` 时，使用了 `transform` 的逆变换，将父视图坐标系下的点转换到子视图的 `bounds` 坐标系。[7]
    *   **结论**：界面上能“看见”的地方才能点中，旋转后“空掉”的区域点不中。[7]

3.  **调用次数与视图树规模相关**：一次 hit-testing，调用 `hitTest:withEvent:` 和 `pointInside:withEvent:` 的次数与视图树的广度（兄弟视图数量）直接相关，而非树深度。[5]
    *   **示例**：`root` 下有 52 个子视图，点空白区域时，`hitTest:` 会被调用 53 次（1次 `root` + 52次子视图），子视图全部遍历一遍。[5]
    *   **性能警示**：不要在 `pointInside:` 和 `hitTest:` 中执行复杂操作（如文件读取、数据库查询、大规模排序甚至 `layoutIfNeeded`），代价会随视图规模放大。[5]

4.  **让父视图“更愿意”接收事件**：在 `hitTest:withEvent:` 中，可以在 `pointInside:` 返回 `NO` 的情况下，依然手动遍历子视图，跳过父视图自身的 `pointInside:` 检查，从而实现让区域外的子视图也能响应事件。[8]

## 高频追问

-   **Q：如何扩大按钮的点击区域？**
    -   **思路**：创建 `UIButton` 的子类，重写 `pointInside:withEvent:`。在该方法中，将对 `bounds` 的检查范围扩大（例如增加一个 `offset`）。[11]

-   **Q：父视图 `clipsToBounds = YES`，超出区域的子视图还能响应点击吗？**
    -   **回答**：不能。`clipsToBounds = YES` 只是裁剪了超出区域的视觉显示，而 `pointInside:` 的逻辑依然返回 `NO`，导致 hit-testing 无法继续深入子视图。[1]

-   **Q：事件传递和响应者链的区别是什么？**
    -   **回答**：事件传递（Hit-Testing）是**自上而下**的，目的是**找到**响应事件的视图。响应者链（Responder Chain）是**自下而上**的，目的是**处理**事件。一个视图的 `nextResponder` 决定了事件未被处理时应该向谁传递。[2][9]

-   **Q：`UIViewController` 在响应者链中处于什么位置？**
    -   **回答**：如果事件的第一响应者是 `UIViewController` 的 `rootView`，并且 `rootView` 不处理该事件，那么 `nextResponder` 会指向其所在的 `UIViewController`，而不是 `rootView` 的 `superview`。[2]

-   **Q：如何让父视图和子视图都能响应同一个事件？**
    -   **回答**：在子视图的触摸事件处理方法中（如 `touchesBegan:`），处理完自己的逻辑后，调用 `[super touchesBegan:touches withEvent:event]`，将事件传递给 `nextResponder`。[9]
